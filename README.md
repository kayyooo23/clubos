# ClubOS — серверная часть (v0.3, мультиклубная)

Что умеет: несколько клубов в одной системе; ПК, тарифы (почасовой / пакет / ночной); регистрация гостей по телефону
с подтверждением по SMS; вход по телефону и паролю; баланс (пополнение наличными через сотрудника); игровые сессии
с оплатой с баланса; блокировка ПК; вход сотрудника на ПК → обычный рабочий стол; журнал действий; сменный отчёт.
Архитектура и план — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск
    pip install -r requirements.txt
    python -m alembic upgrade head      # создать/обновить базу (club.db)
    python -m scripts.seed_dev          # демо-клуб, ПК и тарифы; напечатает логин и ключ ПК
    uvicorn app.main:app --reload
    # открой http://localhost:8000/docs — там интерактивная панель API

## Попробовать весь путь (без настоящего клиента)
1. Окно 1: `uvicorn app.main:app --reload` — сюда в dev приходят «SMS» с кодами (строка `[SMS-заглушка → …]`).
2. Окно 2: `python fake_agent.py setup <ключ ПК>` (ключ напечатал seed_dev), затем `python fake_agent.py watch` — показывает, что видит ПК.
3. Окно 3 (гость на ПК): `python fake_agent.py register +79991234567` → код из окна 1 → пароль.
4. В /docs: `POST /api/admin/auth/login` (данные для входа напечатал seed_dev) → скопируй `token` → **Authorize**.
   Найди гостя `GET /api/admin/accounts?phone=…` и пополни: `POST /api/admin/accounts/{id}/topup`.
5. Окно 3: `python fake_agent.py tariffs`, `python fake_agent.py start <id тарифа>` — в окне 2 ПК разблокируется. `stop` — снова заблокируется.
6. Сотрудник на рабочем столе: `python fake_agent.py login <телефон сотрудника>` — в окне 2 появится 🖥, `logout` — снова 🔒.

Для проверки со второго компьютера в сети (например, ноутбука) вместо `uvicorn` используйте `scripts\run_lan.cmd` —
подробности в [client/README.md](client/README.md), раздел «Проверка на втором компьютере». Создать ПК и получить его ключ без админки:
`python -m scripts.add_pc <код клуба> <название ПК>`.

Тесты: `python -m pytest`

## База данных: SQLite и PostgreSQL
По умолчанию сервер работает на SQLite (файл `club.db`): для разработки этого достаточно. Для боевой работы нужна PostgreSQL: `CLUB_DB_URL=postgresql+psycopg://пользователь:пароль@хост:5432/база`, затем `python -m alembic upgrade head`.
Локальная PostgreSQL для разработки без установки и прав администратора: `.\scripts\pg_dev.ps1 start` (скачает официальную сборку, порт 5433, базы `clubos_dev` и `clubos_test`; остановить: `stop`).
Тесты на PostgreSQL: `$env:CLUB_TEST_DB_URL = "postgresql+psycopg://postgres@localhost:5433/clubos_test"; python -m pytest` (имя базы должно оканчиваться на `_test`: тесты пересоздают в ней таблицы).
Подробности, правило блокировок и проверки параллельной работы: ARCHITECTURE.md, раздел «PostgreSQL и порядок блокировок».

## Веб-админка
Открывается на самом сервере: **http://localhost:8000/admin/** (или адрес сервера + `/admin/`). Ничего ставить не нужно.
Вход: код клуба, телефон и пароль сотрудника (для демо-клуба данные напечатал `python -m scripts.seed_dev`).

| Раздел | Что можно |
|---|---|
| Гости | поиск по части номера, баланс, история денег; пополнить наличными, корректировка (с причиной), заблокировать |
| Сессии | история: кто, где, на каком тарифе, сколько стоило |
| Залы и тарифы | залы-шаблоны (обычный зал, VIP, Premium, PS5, Duo): характеристики и свои тарифы у каждого; тарифы добавить (почасовой, пакет, ночной), изменить цену и отключить; скопировать тарифы из другого зала |
| Отчёт | за сегодня / вчера / 7 и 30 дней / свой период: выручка, наличные по кассирам, корректировки, разбивка по тарифам; печать |
| Журнал | кто и когда входил на ПК, принимал деньги, менял баланс и ключи |

Как устроена безопасность админки: страница строится только из текстовых узлов (в коде нет вставки HTML — это проверяет тест),
сервер отдаёт строгую политику CSP (скрипты и стили только с самого сервера, внешние адреса запрещены, показ во фрейме запрещён),
токен входа хранится в `sessionStorage` и пропадает при закрытии вкладки, время везде показывается по часовому поясу клуба.
Файлы админки — обычные HTML/CSS/JS без сборки в `app/web/admin/`.

## Кто с чем работает
| Кто | Чем авторизуется | Что может |
|---|---|---|
| Платформа (владелец продукта) | `X-Platform-Key` | создавать клубы, приостанавливать их, сбрасывать пароль сотрудника: `/api/platform/...` |
| Сотрудник в админке | токен из `/api/admin/auth/login` (Bearer) | всё в своём клубе: ПК, тарифы, гости, пополнение, сессии, отчёт, журнал: `/api/admin/...` |
| Клиент на ПК | `X-PC-Key` (свой у каждого ПК) | состояние, тарифы, регистрация, вход, сброс пароля: `/api/agent/...`, `/api/auth/...` |
| Гость на ПК | `X-PC-Key` **и** токен из входа на этом ПК | кабинет: `/api/me/...` (баланс, история, старт/стоп сессии) |

Клуб сервер определяет сам по ключу ПК или токену, поэтому клуб А не может увидеть или изменить данные клуба Б.
Токены привязаны к назначению: токен, выданный на ПК, не открывает админку, а токен админки не работает на ПК.

## Как это устроено
    app/config.py         настройки из переменных окружения и лимиты
    app/db.py             подключение к БД (SQLite-файл club.db)
    app/models.py         таблицы: клубы, ПК, тарифы, аккаунты, входы, сессии, коды SMS, журнал денег, аудит
    app/security.py       хеш паролей (argon2), токены и ключи ПК (в БД только их хеш)
    app/deps.py           «контекст клуба»: ключ ПК / токен → какой это клуб, кто это
    app/services/         вся логика:
        billing           деньги и время (стоимость, ночное окно, конец почасовой сессии по балансу)
        wallet            ЕДИНСТВЕННОЕ место, меняющее баланс (журнал + защита от минуса)
        sessions          старт / стоп / закрытие по времени и по деньгам
        logins            кто вошёл на ПК: правила «один вход на ПК», кабинет гостя, рабочий стол сотрудника
        verification      коды SMS и лимиты на них
        sms/              провайдер SMS (console — заглушка для dev; реального подключаем одним файлом)
        cashier, accounts, clubs, audit
    app/routers/          HTTP-эндпоинты: platform, admin_auth, admin, agent, auth, me
    app/webui.py          раздача веб-админки (/admin) и защитные заголовки
    app/web/admin/        сама админка: HTML, CSS и JavaScript без сборки
    alembic/              миграции БД
    tests/                автотесты (изоляция клубов, SMS, вход, деньги, сквозной сценарий)
    scripts/seed_dev.py   демо-данные для разработки
    fake_agent.py         имитация клиента на ПК гостя

Настройки (переменные окружения): `CLUB_DB_URL`, `CLUB_PLATFORM_KEY` (в проде обязательно свой), `CLUB_ENV=prod`,
`CLUB_SMS_PROVIDER`, `CLUB_STAFF_TOKEN_HOURS`. Остальное — в `app/config.py`.
В `CLUB_ENV=prod` сервер не стартует с ключом платформы по умолчанию и с SMS-заглушкой.

## Миграции БД
После изменения `app/models.py`:

    python -m alembic revision --autogenerate -m "что изменилось"
    python -m alembic upgrade head

Автогенерацию всегда проверяй глазами. Тесты `tests/test_migrations.py` упадут, если модели и миграции разошлись
или если миграция потеряла условие `WHERE` у частичного индекса (в SQLite изменение колонки пересоздаёт таблицу).

## Как работает блокировка
Клиент на ПК раз в пару секунд спрашивает `GET /api/agent/state`:
- `locked` — экран блокировки; если в ответе есть `account`, гость вошёл и видит кабинет (баланс, тарифы);
- `guest_session` — идёт игровая сессия, ПК разблокирован;
- `staff_desktop` — вошёл сотрудник: обычный рабочий стол, без тарифа и оплаты.
Сессия закончилась (стоп, вышло время или кончились деньги) — ПК блокируется. Приостановленный клуб — все его ПК заблокированы.

## Бар и вызов администратора
- Гость на своём ПК открывает вкладку «Бар», собирает заказ и платит с баланса. Сотрудник видит заказ в админке («Заказы») с названием ПК,
  двигает его: принять, выдан, отменить (деньги вернутся гостю). Гость может отменить свой заказ, пока его не приняли.
- Кнопка «Вызвать администратора» создаёт вызов (один открытый на ПК); сотрудник закрывает его кнопкой «Подошёл».
- Меню бара ведётся в админке, раздел «Бар». Стартовое меню: `python -m scripts.seed_catalog demo` (вместе со стартовым набором игр).

## Карта клуба и железо
- Вкладки «Компьютеры» нет (объединена с картой): в панели выбранного ПК сотрудник запускает и останавливает сессию, **пополняет баланс гостя по номеру ПК** (кнопка «Пополнить баланс», деньги получает тот, кто сейчас за этим ПК), блокирует ПК, ставит на обслуживание, выдаёт ключ; «+ Добавить ПК» в шапке карты. Кнопка «Пополнить» есть и рядом с каждым вызовом администратора в «Заказах».
- Поля телефона в админке принимают только цифры и сами собирают номер в «+7 (900) 123-45-67».
- В админке «Карта клуба» ПК расставляются по залам перетаскиванием («Расставить ПК»), на карте видно, кто играет, кто свободен, какой ПК
  не на связи или на обслуживании. По щелчку открывается панель ПК: сессия, заметка, железо. ПК на обслуживании гостей не пускает.
- Клиент на ПК сам присылает характеристики железа; если конфигурация изменилась, ПК помечается восклицательным знаком, пока сотрудник не подтвердит.
- «Дашборд» показывает сводку за сегодня.

## Резервные копии и состояние сервера
- Базу копирует команда `python -m scripts.backup` (по расписанию): копия проверяется, старые копии убираются по схеме 14 суток, 8 недель, 12 месяцев, можно класть вторую копию на другой диск (`--copy-to`). Восстановление: `python -m scripts.restore ФАЙЛ --target АДРЕС_БАЗЫ`. Копию, которую ни разу не восстанавливали, считайте ненадёжной: проверяйте раз в месяц на отдельной базе.
- Панель платформы, вкладка «Сервер»: состояние базы и схемы, ПК на связи, последняя копия и предупреждения (нет копий, не удалась, устарела). Адрес `/api/health` для внешнего мониторинга: 200 жив, 503 нет.
- Развёртывание на сервере (Docker Compose с PostgreSQL и HTTPS): `deploy/server/README.md`.

## Синхронизация игр
- Игру ставят или обновляют один раз на «эталонном» ПК, а админка копирует её на остальные ПК клуба: вкладка «Синхронизация», выбрать эталон, игры (список приходит с самого ПК, для игр Steam копируется и их `appmanifest`) и получателей. Файлы идут по локальной сети между ПК, облачный сервер только координирует.
- Копируются только изменившиеся части файлов (блоки по 4 МБ, каждый проверяется по хешу), а ПК, уже получившие игру, раздают её остальным, поэтому эталон не перегружается. ПК копируют, когда свободны (на экране блокировки, без гостя). Видно ход по каждому ПК, задание можно отменить.
- Настройка: на каждом ПК в настройках клиента задаётся игровая папка (`install.ps1 -GamesRoot D:\Games`; это же открывает порт раздачи для локальной сети). Подробности: `client/README.md`, `ARCHITECTURE.md`.

## Автообновление клиента
- ПК клуба сами обновляют клиент: владелец платформы собирает версию (`client\deploy\publish.ps1 -Version 1.2.0 -Zip`), подписывает её своим закрытым ключом (`ClubOS.Release sign`) и загружает в панели платформы (`/platform/`, «Версии клиента»). Загруженная версия никому не раздаётся, пока её не включат; её можно выдавать постепенно (доля ПК, отдельные клубы). ПК ставит новую версию, когда свободен (экран блокировки, гостя нет), а если она не заработала, сам возвращает прежнюю.
- Подлинность версии доказывает подпись, а не сервер: даже взломанный сервер не может запустить свой код на ПК. Без ключа подписи в программе автообновление выключено. Подробности и порядок выпуска: `client/README.md`, раздел «Автообновление», и `ARCHITECTURE.md`.
- В панели ПК (админка) видна версия клиента и, если обновление не удалось, причина.

## Подключение ПК по коду и команды ПК
- На карте клуба кнопка «Подключить ПК по коду»: создайте код (срок, сколько ПК можно подключить, зал для новых ПК) и на каждом ПК установите клиент командой `install.ps1 -Server <адрес> -EnrollCode <код>`. ПК сам подключится к клубу, получит свой ключ, встанет в выбранный зал; останется расставить его на карте. Код показывается один раз, его можно отозвать.
- Ключ привязан к компьютеру: если диск скопировали на другой ПК, копия получит отказ и подключится по коду как отдельный ПК, а в панели оригинала появится отметка.
- В панели ПК кнопки «Перезагрузить» и «Выключить» (с подтверждением; при идущей сессии гостя отдельное предупреждение), «Команда ПК» в шапке карты для нескольких ПК сразу. ПК выполняет команду через 20 секунд и присылает результат; не на связи: команда ждёт десять минут. Включить выключенный ПК из админки пока нельзя.

## Залы как шаблоны для ПК
- В разделе «Залы и тарифы» заводятся залы клуба: обычный зал, VIP, Premium, PS5, Duo (названия любые). У зала есть название, характеристики (процессор, видеокарта, память, монитор, периферия, заметка) и свои тарифы.
- При добавлении ПК выбирается зал: ПК попадает в этот зал на карте, получает его тарифы, а цены и характеристики вводить заново не нужно. Новый зал можно сразу заполнить тарифами другого зала («Скопировать тарифы из...») и поправить цены.
- Гость на ПК видит только тарифы своего зала. Если у зала своих тарифов нет, действуют общие тарифы клуба (раздел «Общие тарифы»), так что клуб без залов работает как раньше. Продление пакетом и доплата по часам после пакета тоже считаются по тарифам зала.
- ПК можно перевести в другой зал в панели ПК на карте или перетащив его в другой зал в режиме «Расставить ПК»: тарифы сменятся, идущая сессия доработает по прежнему.
- «Изменить» тариф создаёт его новую версию (старая отключается): идущие сессии и отчёты не ломаются.

## Сообщение гостю на экран
- Гость шумит или нужно что-то сказать, а идти через зал не хочется: выберите ПК на карте клуба, нажмите «Сообщение гостю», выберите готовую фразу или напишите свой текст (до 300 знаков) и отправьте. Гость увидит окно «Сообщение от администратора» в углу экрана поверх меню и игры, со звуком; если игра в «настоящем» полноэкранном режиме, сообщение выходит на весь экран и забирает фокус до нажатия «Понятно», после чего игра возвращается. В панели ПК видно, дошло ли сообщение («показано на ПК в 14:05»). Если ПК не на связи, сообщение дойдёт, только если связь вернётся в течение двух минут.

## Бронирование
- Сотрудник бронирует ПК на номер гостя («Бронирование» в админке). За 30 минут до начала и 15 минут после начала ПК держится за этим гостем, другой сессию
  на нём не начнёт. Не пришёл за 15 минут, ПК освобождается. На карте клуба такой ПК помечен «Бронь».
- Занятый ПК бронировать нельзя: если за ПК сидит гость (даже не начавший игру), идёт сессия или вошёл сотрудник, бронь на это время сервер отклонит. Гость пришёл к стойке: в панели ПК на карте кнопка «Занять для гостя» (номер гостя), ПК сразу показывается занятым («Ждём гостя»), а если гость не сел за 15 минут, освобождается сам.
- Бронь можно изменить: «Изменить» двигает время (быстрые кнопки +15 мин, +30 мин, +1 ч, +2 ч, если гость позвонил и не успевает), длительность, ПК, номер и имя; «Комментарий» записывает пожелание гостя (например, другая мышь или клавиатура), оно видно в списке и на карте клуба. Закрытую бронь менять нельзя.

## Меню гостя, продление, обложки
- После входа гость видит «Библиотеку»: сверху игры плакатами, под линией программы. Справа всегда видно сколько осталось времени и баланс, а под ними
  кнопки «Продлить тариф», «Пополнить баланс», «Вызвать администратора» и «Завершить сессию».
- Продлить можно пакетом часов посреди игры (если сессия начата с пакета или ночи): цена списывается с баланса сразу, время добавляется к оплаченному.
  Если пакет уже кончился и шла доплата по часам, сначала закрывается доплата. Если на этот ПК скоро бронь другого гостя, продлить нельзя.
  «Пополнить баланс» пока вызывает администратора (оплату на стойке), онлайн-оплата появится после выбора провайдера.
- Обложки игр из Steam подтягиваются сами: сервер берёт постеры в фоне, когда вы добавили игру или ПК открыл меню (кнопку нажимать не нужно, постеры появляются через несколько секунд; сервер обращается в Steam не чаще раза в 10 минут). Кнопка «Подтянуть обложки из Steam» в админке «Игры» остаётся, чтобы сделать это сразу, и «Обложка» у каждой игры для своей
  картинки (PNG или JPEG до 2 МБ, лучше 600 x 900). Загруженная вручную обложка главнее. У игры без обложки плитка с буквой.

## Браузеры в режиме инкогнито
- Браузеры, запущенные гостем из меню (Chrome, Edge, Firefox, Brave, Opera, Vivaldi, Яндекс Браузер), всегда открываются в приватном режиме. Ничего настраивать не нужно: клиент узнаёт браузер по имени файла и сам добавляет ключ запуска. Подробности и про принудительные политики браузера: [client/README.md](client/README.md).

## Выбор программы на ПК
- Добавляя программу в меню («Игры» → «Добавить игру», способ «Файл на ПК»), нажмите «Выбрать на ПК»: откроется список программ, найденных на выбранном компьютере клуба Иконка программы (та, что видна в Windows) подтягивается сама: в меню гостя плитка будет с иконкой вместо буквы, и у программ, добавленных раньше, иконки тоже появятся, как только ПК пришлёт список (нажмите «Обновить список», если ждать не хочется). Свою картинку можно загрузить в таблице, она главнее.
  (ярлыки в меню «Пуск»). Установили новую программу, нажмите «Обновить список» и подождите несколько секунд. Путь и название подставятся сами.
- Программы лучше ставить для всех пользователей Windows (`Program Files`): путь одинаков для всех ПК клуба, а гости играют под другим пользователем.

## Реклама партнёров
- Рекламодатель присылает вам готовый баннер. Владелец платформы открывает `/platform/` (вход по ключу платформы), загружает картинку (PNG или JPEG
  до 2 МБ, лучше всего 1920 x 1080, то есть 16 на 9, на весь экран), указывает рекламодателя, erid и сколько секунд показывать, и смотрит отчёт по показам.
- Клуб сам включает рекламу на вкладке «Реклама» в админке и получает указанную долю дохода. Пока ПК простаивает, баннер идёт на весь экран; гость нажимает
  кнопку мыши или клавишу, и открывается форма входа. На баннере метка «РЕКЛАМА». Если баннеров несколько, они сменяют друг друга.
- Время показа считает сервер. Ключ платформы никому не передавайте; на настоящем сервере включайте HTTPS.

## Деньги
- Баланс в целых рублях; меняется только через `services/wallet.py`, каждая операция записана в журнал `wallet_transactions`.
- `package` / `night`: вся цена списывается при старте. `hourly`: списывается при закрытии за фактическое время,
  а конец сессии = момент, когда на балансе кончатся деньги (пополнение во время игры продлевает сессию).
- Ночной тариф действует по **местному времени клуба** (`utc_offset`), окно через полночь (23 → 8) поддерживается.
- Доплата по часам: когда пакет или ночь кончились, а на балансе есть деньги, игра продолжается по цене самого дешёвого почасового тарифа клуба (120 ₽/ч = 2 ₽ в минуту), пока хватает баланса; пополнение продлевает игру. Если в клубе нет почасового тарифа, доплаты нет.
- Продление пакетом во время игры (`POST /api/me/sessions/extend`) списывает цену сразу; сумма продлений входит в стоимость сессии.
- Возвратов нет: пакет сгорает при досрочной остановке. Исправить ошибку можно ручной корректировкой (`/adjust`, комментарий обязателен).
