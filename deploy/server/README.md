# Развёртывание сервера ClubOS

Сервер, база и HTTPS на одном арендованном сервере (VPS) через Docker Compose. **Файлы этой папки на ПК разработки не запускались (там нет Docker), их проверка ждёт первого настоящего развёртывания:**
идите по шагам и сразу проверяйте результат. Всё, что относится к копиям и восстановлению базы, проверено отдельно, тестами и вживую.

## Что нужно
- Сервер с Linux (Ubuntu 24.04 или подобный), от 2 ГБ памяти и 20 ГБ диска плюс место под версии клиента (пакет около 106 МБ) и копии базы; Docker и плагин Docker Compose.
- Доменное имя, запись A которого указывает на сервер. Порты 80 и 443 открыты (80 нужен Caddy, чтобы получить сертификат). Больше ничего наружу открывать не нужно.
- **Настоящий SMS-провайдер.** Боевой режим (`CLUB_ENV=prod`) без него намеренно не запускается: гости не смогут зарегистрироваться, а коды из консоли в боевой системе недопустимы. Пока провайдер не выбран и не подключён,
  сервер можно поднять только для закрытой проверки в режиме разработки (`CLUB_ENV=dev`): коды регистрации тогда печатаются в журнале сервера, ключ платформы всё равно задаётся вами. В клубе с настоящими гостями так не работайте.

## Первый запуск
```bash
git clone <адрес репозитория> clubos && cd clubos/deploy/server
cp .env.example .env && nano .env        # DOMAIN, DB_PASSWORD, PLATFORM_KEY (случайные длинные значения: openssl rand -base64 32)
docker compose up -d --build
docker compose ps                        # db, app, caddy должны быть «healthy» или «running»
curl https://<ваш-домен>/api/health      # {"ok":true,"db":true,"schema":"ok"}
```
Первый вход: `https://<домен>/platform/` и ключ платформы; там заводятся клубы (`POST /api/platform/clubs` или вкладка «Клубы»). Миграции базы применяются при каждом запуске приложения сами.

## Обновление сервера
1. Сделайте копию базы (команда ниже) и убедитесь, что она появилась.
2. `git pull && docker compose up -d --build`. Миграции применятся при старте; `curl .../api/health` должен снова ответить `"schema":"ok"` (если схема старше кода, он ответит 503: значит, миграция не прошла, смотрите `docker compose logs app`).

## Резервные копии (обязательно настроить сразу)
В базе балансы и история денег гостей: потеря базы это потеря денег. Копию делает команда `python -m scripts.backup` (проверяет копию, хранит 14 суток, 8 недель и 12 месяцев, пишет `backup-status.json`;
владелец платформы видит результат на вкладке «Сервер» и получает предупреждение, если копия старше 26 часов или попытка не удалась).

Раз в сутки (лучше каждые несколько часов), на сервере, в `crontab -e`:
```
15 */6 * * *  cd /opt/clubos/deploy/server && docker compose exec -T app python -m scripts.backup --copy-to /data/backups-second >> /var/log/clubos-backup.log 2>&1
```
Копия в томе Docker на том же сервере **не защищает от потери самого сервера или диска**. Обязательно увезите копии в другое место, например в облачное хранилище с помощью rclone:
```
30 */6 * * *  rclone copy "$(docker volume inspect clubos_data -f '{{ .Mountpoint }}')/backups" remote:clubos-backups --include "club-*.pgdump"
```
Копии содержат телефоны гостей: хранилище должно быть закрыто паролем или ключом доступа.

**Раз в месяц проверяйте, что копию можно восстановить** (копия, которую не проверяли, это надежда, а не защита). На отдельной базе, не на рабочей:
```bash
docker compose exec -T db createdb -U clubos clubos_check
docker compose exec -T app python -m scripts.restore /data/backups/club-ГГГГММДД-ЧЧММСС.pgdump --target postgresql+psycopg://clubos:<DB_PASSWORD>@db:5432/clubos_check
# должно напечатать число строк в таблицах clubs, accounts, wallet_transactions
docker compose exec -T db dropdb -U clubos clubos_check
```

## Восстановление после аварии
Рабочую базу восстанавливают только при остановленном приложении:
```bash
docker compose stop app
docker compose run --rm app python -m scripts.restore /data/backups/club-ГГГГММДД-ЧЧММСС.pgdump --target postgresql+psycopg://clubos:<DB_PASSWORD>@db:5432/clubos
docker compose start app
```
Если сервер потерян целиком: новый сервер, первый запуск по шагам выше, затем восстановление последней копии из облака этой командой. Все данные после последней копии потеряны, поэтому копии должны быть частыми.

## Наблюдение
- Вкладка «Сервер» в панели платформы: состояние базы и схемы, ПК на связи, последняя копия и предупреждения.
- Внешний монитор (UptimeRobot, Better Stack и подобные) на адрес `https://<домен>/api/health`: ответ 200 означает «жив», 503 «база не отвечает или схема старше кода». Цифр о клубах этот адрес не раскрывает.
- Журнал: `docker compose logs -f app`.

## Безопасность
- Ключ платформы даёт доступ ко всем клубам: храните в менеджере паролей, смените, если он мог попасть к посторонним (правится в `.env`, затем `docker compose up -d`).
- Порт приложения наружу не открыт: доверие к адресу ПК из заголовка прокси держится на этом, не публикуйте `8000`.
- Закройте вход по паролю на самом сервере (только ключи SSH) и держите систему обновлённой.

## Без Docker
Приложение это обычный `uvicorn app.main:app` (Python 3.14, `pip install -r requirements.txt`, `python -m alembic upgrade head`) за любым обратным прокси с HTTPS и PostgreSQL по адресу в `CLUB_DB_URL`.
Не забудьте `--proxy-headers`, если прокси передаёт `X-Forwarded-For`, и расписание `python -m scripts.backup` (Планировщик заданий Windows или cron).
