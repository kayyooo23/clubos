# ClubOS: контекст проекта для Claude Code

ClubOS: продукт для компьютерных клубов. Владелец продукта говорит по-русски, пишем по-русски (интерфейс, документация, ответы).

## Из чего состоит
- **Сервер** (`app/`): FastAPI + SQLAlchemy + Alembic (миграции `alembic/versions`, сейчас до 0019), много клубов в одной базе (по `club_id`).
- **Админка клуба** (`app/web/admin/`, адрес `/admin/`) и **панель владельца платформы** (`app/web/platform/`, `/platform/`): чистый JS без сборки, DOM строится только через `h()` (никакого innerHTML, строгий CSP).
- **Клиент для ПК гостя** (`client/`, Windows, .NET 10): служба `ClubOS.Service` (права SYSTEM, связь с сервером, очистка ПК, список программ с иконками) и оверлей `ClubOS.Overlay` (WPF: экран блокировки, вход, меню гостя).
- Подробности: `ARCHITECTURE.md` (главный документ), `README.md` (запуск), `client/README.md` (клиент, пакет для второго компьютера), `THIRD-PARTY.md` (шрифты и лицензии).

## Как запускать и проверять
```
pip install -r requirements.txt
python -m alembic upgrade head          # создать/обновить club.db
python -m uvicorn app.main:app --reload # сервер; в dev «SMS» с кодами печатаются в это окно
python -m pytest -q                     # тесты сервера и админки (около 3 минут; JS-тесты идут через Node)
cd client; dotnet test ClubOS.Client.slnx   # тесты клиента (около 15 секунд)
```
Нужны: Python 3.14, .NET 10 SDK, Node.js. Для проверки со второго ПК в сети: `scripts\run_lan.cmd`, пакет для ноутбука: `client\deploy\make-test-package.ps1` (см. `client/README.md`).

Ловушки:
- Перед `dotnet test` обязательно остановить запущенные `ClubOS.Overlay` и `ClubOS.Service` (из любой папки): при работающем оверлее около 50 оконных тестов падают с «Ресурс "Text" не найден», при работающей службе падают 2 теста. Дело не в блокировке файлов, причина не выяснена; без этих процессов все тесты зелёные.
- Для разработки службе и оверлею нужны **одинаковые** `CLUBOS_COVERS_DIR` и `CLUBOS_ADS_DIR` (если их задают): служба кладёт туда обложки и баннеры, а оверлей принимает только пути внутри своей папки. Задали только службе, и в меню у игр и программ вместо картинок остаются буквы, хотя файлы скачаны.
- **PostgreSQL.** Сервер и тесты работают и на SQLite (по умолчанию), и на PostgreSQL. Локальная база: `scripts\pg_dev.ps1 start` (порт 5433, лежит в `C:\clubos-tools`, там же архив: заново качать не нужно). Тесты на ней: `$env:CLUB_TEST_DB_URL = "postgresql+psycopg://postgres@localhost:5433/clubos_test"; python -m pytest`; параллельные тесты `tests/test_postgres_concurrency.py` идут только на PostgreSQL. Новый код проверяйте на обеих.
- **Порядок блокировок: сначала аккаунт (`wallet.lock`), потом сессия, потом остальное.** Иначе на PostgreSQL получится взаимная блокировка (шторм-тест её находит). Деньги меняет только `wallet.apply` (атомарный условный UPDATE). Всё, что закрывает сессию или списывает деньги, должно быть идемпотентным при одновременных запросах (см. `_finalize`).
- **Команды ПК (перезагрузка, выключение) на живой службе реально вызывают `shutdown.exe`.** Для проверки на своём компьютере запускать службу с `CLUBOS_POWER_DRYRUN=1` и перед запуском убедиться, что `dotnet build` прошёл без ошибок (старая сборка без пробного режима перезагрузит ПК). Запланированную перезагрузку снимает `shutdown /a`. Подключение по коду в разработке: `CLUBOS_ENROLL_CODE` без `CLUBOS_PC_KEY`, `CLUBOS_IDENTITY_FILE` и `CLUBOS_COMMANDS_FILE` во временную папку; созданные при проверке ПК и коды из dev-базы удалять.
- **Нативная часть на C++** (`client/ClubOS.Native`, CMake): `client\ClubOS.Native\build.ps1` собирает `out\clubos_native.dll` и гоняет 47 тестов GoogleTest (скачиваются при первой сборке); DLL подхватывают `dotnet build` и `deploy\publish.ps1` (кладётся рядом со службой и оверлеем через `ClubOS.Shared`; обёртки в `ClubOS.Shared/Native`). Перехват клавиш, опрос окон, характеристики ПК и хеши блоков делает она. Без DLL всё то же считается на C# (`CLUBOS_NATIVE=0` отключает нативный подсчёт). В коде на C++: C++20, RAII, без сырых буферов, исключения через границу DLL не выпускать, только системные библиотеки; `gtest_discover_tests` не использовать (ломается на кириллице в пути профиля).
- **Автообновление клиента** вызывает `sc.exe config` и `schtasks` для службы `ClubOSAgent` и задачи `ClubOS Overlay`, останавливает службу и убивает `ClubOS.Overlay`. Живую проверку (служба из папки `versions\<версия>\Service`, `CLUBOS_RELEASE_PUBLIC_KEY_FILE`, `CLUBOS_UPDATES_DIR`, `CLUBOS_POWER_DRYRUN=1`) делать только там, где настоящей службы ClubOS нет. Закрытый ключ подписи релизов (`*.key`) не в репозиторий и не на сервер; открытый ключ вшит в `client/ClubOS.Service/release-public-key.pem`. Настоящие `sc.exe` и остановка службы проверены только на подмене (`IUpdateHost`).
- **Синхронизация игр** (`client/ClubOS.Service/Sync`): в разработке несколько экземпляров службы на одном ПК различаются `CLUBOS_GAMES_ROOT`, `CLUBOS_SYNC_PORT`, `CLUBOS_SYNC_BIND=127.0.0.1`, `CLUBOS_SYNC_ADVERTISE`, `CLUBOS_SYNC_DIR` и `CLUBOS_PIPE`, а также своими ключами ПК; тестовые ПК, задания и игровые папки после проверки удалять. Служба из папки `bin` автообновление не включает и обновлять себя не станет.
- **Тесты на PostgreSQL не запускать двумя процессами сразу**: они пересоздают таблицы в одной базе `clubos_test`, второй процесс зависает на блокировках. Перед запуском проверить, что нет старого `pytest` (`Get-CimInstance Win32_Process | where CommandLine -match pytest`). Для долгих запусков в фоне писать вывод в файл, а не в конвейер.
- Скрипты правок на Python, созданные через `<<'EOF'` в Bash, «съедают» обратные слэши в якорях: длинные правки делать файлом (инструмент записи) или через `Edit`; скрипты PowerShell с кириллицей пишут в UTF-8 с BOM, а путь к exe с кириллицей лучше передавать параметром.
- Скрипты правок с `str.replace` молча ничего не делают, если якорь не найден: после правки проверять, что изменение попало в файл (`grep`) и что сборка проходит, а не полагаться на «ok».
- Тесты клиента и `pytest` лучше не запускать одновременно (несколько WPF-тестов становятся нестабильными).
- Перед миграцией основной `club.db` делать копию (`club.db.bak-before-...`). Базы в git не лежат.
- Видимые тексты интерфейса: без длинных тире (это проверяет тест).

## Как работать с владельцем (важно)
- Этапы по очереди, без лишних вопросов; решения по умолчанию принимать самому и коротко о них сообщать. Спрашивать только то, что действительно выбор владельца (стиль, провайдеры, деньги).
- Каждый этап: сервер + тесты, админка, клиент, проверка вживую (браузер, снимки оверлея), документация, пересборка пакета для ноутбука.
- Тестовые процессы после проверки останавливать, временные файлы удалять.
- Не делать снимков всего экрана и не нажимать клавиши «вслепую»: на ПК владельца открыты его окна. Снимать только окна ClubOS.

## Дизайн, который выбрал владелец
- Основные цвета чёрный и белый, золото только для мелких деталей; белые кнопки с чёрным текстом; красный только для ошибок и опасных действий, зелёный и оранжевый для состояний.
- Шрифт Manrope (встроен в клиент и админку), иконки Phosphor, обычный регистр без крупных заглавных букв, без системных окон Windows (своё окно подтверждения).
- Меню гостя: слева выдвижная панель по наведению со стрелкой-подсказкой, справа плитки-иконки с малым количеством текста, внизу круглая мигающая точка «Идёт сессия». Вход: карточка по центру без названия клуба, телефон только цифрами с маской `+7 (900) 123-45-67`, у пароля глазок. Все поля ввода одной высоты.
- Библиотека гостя: игры плакатами, ниже компактные плитки программ; у игр обложка (постер), у программ иконка из самого exe. Решения по тарифам, продлению, предупреждениям, очистке ПК, рекламе и админке записаны в `ARCHITECTURE.md`.
- Админка: «Компьютеры» объединены с «Картой клуба» (пополнение по номеру ПК там же), у брони есть комментарий и правка со сдвигом времени, программу в меню добавляют кнопкой «Выбрать на ПК».

- Игры, которые гость скачал в Steam сам (непопулярные): остаются на том ПК, где он их скачал, автоочистку и «гостевую библиотеку» не делаем (решение владельца 13.10.2026). Гость запоминает ПК и садится за него, а если ПК занят, садится за другой; время загрузки компенсирует администратор (корректировка баланса).

Не переспрашивать то, что уже решено, и делать новое в том же стиле.
