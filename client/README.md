# ClubOS — клиент для ПК гостя (Windows)

Программа, которая стоит на каждом клубном ПК: показывает экран блокировки, регистрацию и вход гостя, кабинет с балансом
и тарифами, меню с играми во время сессии и пропускает сотрудника на обычный рабочий стол.
Сервер — в корне проекта (Python), описание архитектуры — в [../ARCHITECTURE.md](../ARCHITECTURE.md).

## Из чего состоит
Основная часть клиента на C#/.NET; нативная библиотека на C++ (`ClubOS.Native`: перехват клавиш киоска, опрос окон, характеристики ПК, хеши блоков для синхронизации игр) собирается отдельно, см. `ClubOS.Native/README.md`.

```
 ПК гостя
 ┌──────────────────────────────────────────────┐
 │ ClubOS.Service  (служба Windows, права SYSTEM)│ ── HTTPS ──▶  сервер ClubOS
 │  • знает КЛЮЧ ПК и токен вошедшего            │
 │  • опрашивает сервер раз в 2 с                │
 │  • решает, что показать, в т.ч. без связи     │
 └───────────────▲──────────────────────────────┘
                 │ именованный канал ClubOS.Agent (локально, по белому списку из 12 операций)
 ┌───────────────┴──────────────────────────────┐
 │ ClubOS.Overlay  (WPF, обычный пользователь)   │
 │  • экран блокировки / меню гостя / трей │
 │  • НЕ знает ни ключа ПК, ни токена            │
 └──────────────────────────────────────────────┘
```

| Проект | Что внутри |
|---|---|
| `ClubOS.Shared` | модели ответов сервера, клиент HTTP API, протокол канала, **вся логика экранов** (`Ui/FlowController`) без привязки к WPF |
| `ClubOS.Service` | служба: `AgentCore` (состояние, офлайн-запас, токен), `PipeServer`, `TokenStore` (токен под защитой DPAPI) |
| `ClubOS.Overlay` | WPF: окна, перехват клавиш (`KioskGuard`), значок в трее |
| `ClubOS.Tests` | 129 автотестов (xUnit) |
| `deploy/` | скрипты: публикация, установка службы, ограничения гостя, удаление |

**Почему две части.** Служба Windows запускается раньше входа в систему и не может показывать окна на рабочем столе пользователя;
окно же работает в сессии гостя — то есть в недоверенной среде. Поэтому ключ ПК и токен живут только в службе (файл с ними закрыт
правами для обычных пользователей), а окно может лишь попросить службу выполнить одну из разрешённых операций.

## Запуск для разработки (безопасно: ничего не блокируется)

Нужен [.NET SDK 10](https://dotnet.microsoft.com/download), сервер из корня проекта запущен (`uvicorn app.main:app`) и ключ ПК
(печатает `python -m scripts.seed_dev`).

```bash
# окно 1 — служба как обычная консольная программа
set CLUBOS_SERVER=http://localhost:8000
set CLUBOS_PC_KEY=<ключ ПК>
dotnet run --project ClubOS.Service

# окно 2 — экран блокировки в обычном окне
dotnet run --project ClubOS.Overlay
```
(в PowerShell: `$env:CLUBOS_SERVER = 'http://localhost:8000'` и т.д.)

Тесты: `dotnet test ClubOS.Tests`

Если задаёте `CLUBOS_COVERS_DIR` и `CLUBOS_ADS_DIR` (папки обложек и баннеров для разработки), задавайте их и службе, и оверлею: служба пишет туда, а оверлей принимает только пути внутри своей папки, иначе в меню останутся буквы вместо картинок.

В режиме разработки оверлей — обычное окно «ПК не блокируется». Полноэкранная блокировка включается только флагом `--kiosk`.
Первую проверку киоска на своём компьютере делайте с флагом **`--allow-exit`**: тогда `Ctrl+Shift+F12` три раза подряд закрывает экран блокировки.

## Режимы ПК (что видит гость)

| Сервер сказал | Что на экране |
|---|---|
| `locked`, гость не вошёл | вход / регистрация по SMS / сброс пароля |
| `locked`, гость вошёл | кабинет: баланс, тарифы (недоступные — с подсказкой «Не хватает N ₽») |
| `guest_session` | экран блокировки скрыт, открыто окно меню: библиотека игр и программ, справа оставшееся время (последние 5 минут оранжевым, последняя минута красным), баланс, «Продлить тариф», «Пополнить баланс», «Вызвать администратора», «Завершить сессию» |
| `staff_desktop` | ничего не закрывает; в трее значок «Заблокировать ПК» |

Если ушла связь с сервером: играющий гость играет дальше до **2 минут** (или до конца оплаченного времени, смотря что раньше), потом ПК
блокируется; сотрудник остаётся за рабочим столом; закрытый ПК остаётся закрытым; после загрузки без связи ПК закрыт.
Вернулась связь — сервер возвращает реальное состояние.

## Меню гостя

После входа гость видит меню: **Библиотека** (сверху игры с категориями, ниже под линией программы; список ведёт администратор в админке, раздел «Игры»; поиск работает по обоим разделам, раздел без совпадений скрывается), **Бар** (заказ еды и напитков
с оплатой с баланса, «Мои заказы», кнопка «Вызвать администратора») и **Тарифы** (во время сессии вкладка называется «Продление»: пакет часов докупается посреди игры, если сессия начата с пакета или ночи; у почасовой сессии время продлевает пополнение). Справа в меню всегда колонка: сколько осталось времени, баланс и кнопки «Продлить тариф», «Пополнить баланс» (пока вызывает администратора), «Вызвать администратора», «Завершить сессию». Игры показаны плакатами с обложками: обложки сервер берёт из Steam или сотрудник загружает вручную, служба скачивает их (с проверкой типа, размера и версии) в `C:\ProgramData\ClubOS\covers` (в разработке `CLUBOS_COVERS_DIR`), а оверлей только читает файлы. Игра без обложки показывается плиткой с буквой, не установленная на этом ПК приглушена. Вход, регистрация и сброс пароля показываются отдельной рамкой по центру окна (слева сверху только «ПК заблокирован» и номер ПК, названия клуба там нет). В поле телефона принимаются только цифры, номер сам собирается в «+7 (900) 123-45-67» (ведущие 7 и 8 принимаются как код страны, вставка «8 900 123-45-67» тоже разбирается), пока поле пустое, видна подсказка. Код из SMS тоже только цифрами. У пароля справа «глазик»: показать пароль открытым текстом (размер рамки не меняется, пароль снова скрывается, когда поле пропадает с экрана). Вкладки меню (Библиотека, Бар, Продление) лежат в левой панели: в покое это узкая полоска со стрелкой, при наведении мыши панель выезжает поверх содержимого. Справа время, баланс и действия плитками со значками (Продлить, Пополнить, Вызвать админа, Завершить), полное название в подсказке. Статус («Идёт сессия», «Тариф закончился», «Сессия не начата») стоит внизу правой колонки круглым мигающим индикатором; вопрос «Завершить сессию?» показывается собственным окном в стиле ClubOS (`ConfirmWindow`), системных окон Windows в интерфейсе нет. Кнопки «Свернуть меню» нет. В режиме разработки меню сворачивает панель задач, а при запуске игры оно сворачивается само; в режиме киоска (`--kiosk`) меню на весь экран и не сворачивается совсем (подробнее ниже, «Меню во время сессии в режиме киоска»). Пока сессия не началась, ПК закрыт, и игры запускать нельзя:
меню отправит гостя выбрать тариф. Во время сессии в режиме разработки меню живёт в обычном окне (его можно свернуть, вернуться через панель задач).
За 15, 10 и 5 минут до конца времени поверх всех окон появляется короткое уведомление со звуком. В полноэкранной игре с «настоящим»
полноэкранным режимом Windows оно не видно, нужен режим «в окне без рамки».

## Меню во время сессии в режиме киоска

С флагом `--kiosk` (настоящий ПК гостя) меню занимает весь основной экран: без рамки, без значка в панели задач, его нельзя ни свернуть, ни закрыть.
Игры и программы запускаются только из него; запущенная игра открывается над меню, а когда её закрыли, под ней снова меню, а не рабочий стол Windows.
Пока идёт сессия, закрыты клавиши Win и Ctrl+Esc (меню «Пуск», Win+E, Win+D, диспетчер задач); Alt+Tab и Alt+F4 работают, чтобы можно было закрыть игру и вернуться в меню.
Если гость всё же оказался на рабочем столе, в панели задач или в меню «Пуск», меню возвращается само (проверка раз в 0,4 секунды); окно Проводника с папками закрывается;
если игра открылась позади меню, её окно выводится вперёд (в течение 90 секунд после запуска). Без `--kiosk` (разработка) всё по-старому: обычное окно, которое можно свернуть.
Первую проверку киоска на своём компьютере делайте с `--kiosk --allow-exit`: Ctrl+Shift+F12 три раза подряд выходит.
Окна «Открыть файл» внутри игр и браузеров, окна лаунчеров (например, Steam), панель задач при игре не на весь экран и второй монитор этим не закрыты: для этого нужна замена оболочки Windows для гостевого пользователя (следующий этап).

## Сообщения от администратора и надпись на экране блокировки

Администратор может написать гостю из админки (карта клуба, «Сообщение гостю»). Служба получает сообщение с очередным опросом состояния, оверлей показывает его один раз
окном в правом нижнем углу («Сообщение от администратора») поверх всех окон со звуком; окно не забирает фокус у игры и гаснет через 30 секунд или по щелчку.
Видно на экране блокировки, в кабинете и в игре. Если на переднем плане чужая полноэкранная игра (где уголок не виден), сообщение выходит на весь экран и забирает фокус: игра сворачивается,
гость читает, нажимает «Понятно» (или Enter, Esc), и игра возвращается. Предупреждения о конце времени остаются только в углу: в «настоящем» полноэкранном режиме их не видно, нужен режим «в окне без рамки».
Над формой входа показывается и то, что сервер сообщил о самом ПК: «ПК забронирован на 19:30», «ПК на обслуживании», «Клуб приостановлен», а при потере связи «Нет связи с сервером».

## Реклама на экране блокировки

Если клуб включил рекламу, свободный ПК показывает заставку: баннер партнёра на весь экран (картинка другой формы помещается по центру, поля закрашиваются
продолжением её края). На баннере слева внизу метка «РЕКЛАМА», рекламодатель и erid, по центру внизу точки карусели, справа подсказка. Несколько баннеров
сменяют друг друга по кругу, каждый столько секунд, сколько задал владелец платформы. Гость нажимает кнопку мыши или клавишу, и заставка уступает форме входа
(это нажатие в форму не попадает). Если гость отошёл, заставка возвращается: через 45 секунд на пустой форме, через 3 минуты, если что-то введено
(введённое стирается). Без рекламы и пока баннеры не скачаны показывается форма входа, как раньше.
Картинки скачивает служба (с проверкой типа, размера и отпечатка) в папку `C:\ProgramData\ClubOS\ads` (в разработке `CLUBOS_ADS_DIR`), оверлей их
только читает. Список клиент берёт раз в минуту. В кабинете гостя и во время игры заставки нет.

## Браузеры в режиме инкогнито

Браузеры, запущенные из меню, всегда открываются в приватном режиме: история, пароли и куки гостя не остаются на ПК. Клиент узнаёт браузер по имени запускаемого файла и сам добавляет ключ:
Chrome, Brave, Vivaldi, Chromium и Яндекс Браузер `--incognito`, Edge `--inprivate`, Firefox `-private-window`, Opera `--private`. Остальные программы запускаются без аргументов.
Таблица зашита в клиент (файл `ClubOS.Shared/Ui/PrivateBrowsing.cs`): ни гость, ни сервер аргументы не задают. Другой браузер добавляется одной строкой в эту таблицу.
Это режим запуска, а не запрет: Ctrl+N в браузере откроет обычное окно. Чтобы оставить только приватные окна, включите политику браузера на ПК:
у Chrome `IncognitoModeAvailability` = 2, у Edge `InPrivateModeAvailability` = 2 (для других браузеров смотрите их документацию). Политики действуют на весь ПК, в том числе на режим сотрудника.

## Список программ для меню

Служба находит программы на ПК (ярлыки в меню «Пуск» и на рабочих столах всех пользователей Windows) и присылает их список серверу: при запуске, раз в два часа, если он изменился,
и сразу, когда администратор нажал в админке «Обновить список». Из этого списка администратор выбирает программу для меню гостя кнопкой «Выбрать на ПК», и путь к exe подставляется сам.
Удаление, справка, установщики и системные файлы в список не попадают. Сам список ничего не запускает и не меняет.
Вместе с названием и путём служба присылает иконку программы (PNG 96 x 96, до 28 КБ), которую Windows берёт из самого exe; у программы без иконки в меню остаётся плитка с буквой.

## Очистка ПК после сессии

Когда сессия гостя кончилась, служба сама закрывает его программы и убирает его данные: браузеры, вход в Steam, Discord, Telegram, Загрузки,
Документы, Temp и так далее (полный список и правила в ARCHITECTURE.md). Оверлей очищает буфер обмена.

Настройки в `agent.json` (пример ниже с пояснениями после `//`; в настоящем файле комментариев быть не должно):

    {
      "server": "https://...", "pc_key": "...",
      "guest_user": "guest",        // Windows-пользователь, под которым играют гости: очистка работает ТОЛЬКО в его сессии
      "cleanup": "on",              // off, dry-run (только пишет в журнал) или on
      "cleanup_paths": ["AppData\\Roaming\\MyLauncher"],   // свои папки в профиле гостя (необязательно)
      "cleanup_keep": ["RGBSoftware"]                       // процессы, которые никогда не закрывать (необязательно)
    }

`install.ps1` записывает `guest_user` и `cleanup` сам (параметр `-Cleanup on|dry-run|off`, по умолчанию `on`).
Без `guest_user` очистка не работает. Сначала посмотрите, что она сделает: `"cleanup": "dry-run"`, затем смотрите журнал службы.

## Оформление

Экран блокировки и веб-админка сделаны в одном стиле: почти чёрный фон, белый для главного (текст, главные кнопки с чёрным текстом) и золото только для мелких деталей (полоски, подписи,
рамки при наведении и в фокусе, значки), прямые углы, рамки 2 px, шрифт Manrope (лежит внутри программы, папка `ClubOS.Overlay/Fonts`, лицензия OFL), значки Phosphor (MIT, `Icons.xaml`). Зелёный и оранжевый цвета нужны только
для состояний (на связи, мало времени), красный только для ошибок и опасных действий. Все цвета и размеры экрана блокировки лежат в одном месте:
`ClubOS.Overlay/App.xaml`; у админки это переменные в начале `app/web/admin/style.css`. Название клуба и номер ПК на экране
берутся из ответа сервера (`club_name`, `pc_name`).

## Проверка на втором компьютере (без установки)

Самый быстрый способ увидеть программу «как в клубе»: один компьютер — сервер, второй (ноутбук) — гостевой ПК.

1. **Сервер.** На ПК-сервере: `scripts\run_lan.cmd` — слушает только адрес локальной сети (не VPN), ключ платформы на время запуска случайный,
   коды «SMS» печатаются в это окно. Один раз выполните `scripts\allow_lan_port.cmd` **от имени администратора**: оно открывает порт 8000
   только для вашей подсети (убрать: `scripts\remove_lan_port.cmd`).
2. **ПК для ноутбука:** `python -m scripts.add_pc demo Laptop --server http://<адрес-сервера>:8000 --write-agent-json agent.json`
   (ключ попадает прямо в файл), затем `client\deploy\make-test-package.ps1 -AgentJson agent.json` — получится `client\dist\ClubOS-laptop-test.zip`.
3. **Ноутбук:** распаковать, `check-connection.cmd` (связь и ключ), `run-windowed.cmd` (безопасный режим — обычное окно),
   потом `run-kiosk-test.cmd` (настоящая блокировка; выход — Ctrl+Shift+F12 три раза). Подробная инструкция лежит в самом архиве (`README.txt`).

## Установка на клубный ПК

1. **На своём компьютере:** `.\deploy\publish.ps1` → появится папка `dist` (самодостаточная, .NET на клубном ПК ставить не нужно).
2. **На клубном ПК:** создайте обычного (не администратора) локального пользователя для гостей, например `guest`, и один раз войдите им.
3. Скопируйте `dist`, откройте PowerShell **от имени администратора** и посмотрите, что будет сделано:
   ```powershell
   .\install.ps1 -Server https://ваш-сервер -EnrollCode <код подключения> -GuestUser guest -WhatIf
   ```
   Затем то же без `-WhatIf`. Скрипт ставит службу `ClubOSAgent`, закрывает папку `C:\ProgramData\ClubOS` (там ключ ПК) правами только для
   системы и администраторов и создаёт задачу, которая запускает экран блокировки при входе гостя и перезапускает его, если он упал.
4. `.\harden-guest.ps1 -User guest` (сначала с `-WhatIf`) — запрещает гостю диспетчер задач, командную строку, реестр, «Выполнить», панель управления.
5. Включите автовход пользователя `guest` и перезагрузите ПК.

Код подключения создаётся в админке («Карта клуба», «Подключить ПК по коду»), один на все ПК зала: служба при первом запуске сама подключается к клубу, получает ключ и хранит его зашифрованным (`C:\ProgramData\ClubOS\identity.bin`), вводить ключи руками не нужно. Тот же компьютер при повторной установке получает свой ПК с новым ключом, а не второй. Прежний способ работает: `-PcKey <ключ>` вместо `-EnrollCode` (ключ создаётся в админке, «Добавить ПК», показывается один раз). Для разработки: `CLUBOS_ENROLL_CODE`, `CLUBOS_IDENTITY_FILE`, `CLUBOS_COMMANDS_FILE`, `CLUBOS_POWER_DRYRUN=1` (команды ПК подтверждаются, но компьютер не перезагружается и не выключается: обязательно при проверке на своём ПК).

Команды «Перезагрузить» и «Выключить» из админки служба выполняет сама через `shutdown.exe` с задержкой 20 секунд, не прерывая сессию гостя без явного подтверждения администратора, и не повторяет их после перезагрузки (журнал `commands.log`). Потерялся или утёк — `POST /api/admin/pcs/{id}/rotate-key`
и повторная установка с новым ключом.

Удаление: `.\uninstall.ps1` (с `-RemoveFiles` удалит и папки).

## Синхронизация игр

ПК копируют игры друг с друга по локальной сети (см. ARCHITECTURE.md, «Синхронизация игр»). Чтобы ПК участвовал, задайте игровую папку: `install.ps1 -GamesRoot D:\Games` (папка с играми или библиотека Steam;
`-SyncPort 47900` меняет порт раздачи). Скрипт пишет `games_root` и `sync_port` в `agent.json` и открывает входящий TCP-порт **только для локальной подсети** (правило «ClubOS Sync»; `uninstall.ps1` его убирает).
Служба раздаёт файлы через `HttpListener` на всех адресах (работает от имени системы, прав хватает), присылает серверу список игр из игровой папки (при запуске, раз в 6 часов и по кнопке «Обновить список игр»)
и копирует по заданиям сервера только когда ПК свободен.

Для разработки (несколько экземпляров службы на одном компьютере): `CLUBOS_GAMES_ROOT` (игровая папка), `CLUBOS_SYNC_PORT` (свой порт у каждого), `CLUBOS_SYNC_BIND=127.0.0.1` (не требует прав),
`CLUBOS_SYNC_ADVERTISE=http://127.0.0.1:ПОРТ` (адрес, который сообщается другим ПК), `CLUBOS_SYNC_DIR` (кэш списка файлов), `CLUBOS_PIPE` (своё имя канала у каждого экземпляра).

## Автообновление

Клиенты обновляются сами, владелец ничего не ставит на ПК руками. Подлинность версии доказывает подпись владельца (ECDSA P-256), сервер её подделать не может.

**Один раз: ключи.** `dotnet run --project client\ClubOS.Release -- keygen --private release-signing.key --public release-public-key.pem` (спросит пароль закрытого ключа; для скрипта
`--password-env ИМЯ`). Закрытый ключ храните отдельно от репозитория и сервера и сделайте копию: потерянный не восстановить, и обновлять станет нечем. Открытый положите в
`client\ClubOS.Service\release-public-key.pem` и пересоберите клиент (он вшивается в программу). Пока там нет ключа, автообновление выключено.

**Каждый выпуск.**
1. `client\deploy\publish.ps1 -Version 1.2.0 -Zip`: версия попадает в программы и в `dist\version.txt`, получается пакет `dist\ClubOS-1.2.0.zip` (около 106 МБ).
2. `dotnet run --project client\ClubOS.Release -- sign --package client\dist\ClubOS-1.2.0.zip --key release-signing.key --notes "что нового"`: версия берётся из самого пакета,
   создаётся `ClubOS-1.2.0.release.json`; проверить подпись можно командой `verify`.
3. Загрузить: панель платформы (`/platform/`, «Версии клиента», «Загрузить версию»: пакет и `.release.json`) или
   `ClubOS.Release upload --server https://... --platform-key ... --package ... --release ... [--activate --percent 5 --clubs 1]`.
4. Версия сначала никому не раздаётся. Включите её для своего клуба или небольшой доли ПК («Выдача»), посмотрите в админке версию клиента на ПК и итог обновления, затем расширьте до 100%.

**Что делает ПК.** Служба раз в 10 минут (первая проверка через 2-4 минуты после запуска, со случайной добавкой) спрашивает сервер о версии; ПК свободен (экран блокировки, гостя нет)
и есть новая версия: скачивает пакет, сверяет подпись и sha256, безопасно распаковывает в `versions\<версия>`, проверяет содержимое и запускает помощника (`ClubOS.Service.exe --apply-update`),
который переключает службу и задачу оверлея на новую версию. Если новая версия за 3 минуты не вышла на связь с сервером, возвращается прежняя. В админке в панели ПК видны версия клиента и причина, если не получилось.

**Раскладка.** `install.ps1` ставит программу в `C:\Program Files\ClubOS\versions\<версия>\{Service,Overlay}` (версия берётся из `version.txt`); хранятся текущая и предыдущая версии.
Служба, запущенная не из такой папки (разработка, пакет для ноутбука), автообновление не включает и ничего не трогает.

**Для разработки.** `CLUBOS_RELEASE_PUBLIC_KEY_FILE` (открытый ключ вместо вшитого), `CLUBOS_UPDATES_DIR` (папка состояния). Служба при переключении вызывает `sc.exe` и `schtasks.exe` для службы
`ClubOSAgent` и задачи `ClubOS Overlay`: на ПК, где они установлены, живую проверку обновления не запускайте. Состояние и журнал помощника: `<updates>\update-state.json`, `apply.log`.

## Что защищено и что нет (честно)

**Защищено:** ключ ПК и токен недоступны оверлею (и процессам гостя); оверлей не может отправить серверу произвольный запрос; токен, выданный
на ПК, не открывает админку; в киоске перехватываются Win, Alt+Tab, Alt+Esc, Ctrl+Esc, Ctrl+Shift+Esc, Alt+F4 (только пока виден экран блокировки);
закрытый экран возвращается на передний план, если его перекрыли; закрыть его крестиком/Alt+F4 нельзя; пароли и токены не пишутся в журнал.

**Не защищено / ограничения:**
- `Ctrl+Alt+Del` из программы перехватить нельзя. Закрыто политиками (`harden-guest.ps1`), но если гость — администратор Windows, защита бессмысленна.
- Загрузка с флешки, безопасный режим Windows, физический доступ к ПК — это не защищается программой (BIOS-пароль, запрет загрузки с USB, BitLocker).
- Режим сотрудника открывает рабочий стол того же пользователя Windows, под которым играют гости, поэтому ограничения гостя действуют и на него.
  Настройку ПК делайте отдельной учётной записью администратора Windows.
- Не тестировалось на реальных клубных ПК с автовходом и политиками: установочные скрипты проверены только на синтаксис, службу я запускал как
  консольную программу (не как службу Windows). Перед выкатом на весь клуб проверьте на одном ПК.
- Несколько мониторов: экран блокировки закрывает основной монитор, остальные не затемняются.
- Ночной тариф в кабинете выглядит доступным и вне ночного окна: отказ приходит от сервера с понятным текстом.
- Нет автообновления клиента и удалённых команд (перезагрузка/выключение) — следующие этапы.
