# ClubOS.Native: нативная часть клиента (C++20)

Библиотека `clubos_native.dll` на C++ для Windows. Остальной клиент (окна WPF, связь с сервером, обновления, меню гостя) написан на C# и .NET: так быстрее разрабатывать, а служба с правами SYSTEM не получает класс ошибок работы с памятью.
На C++ вынесено то, что естественно решается через Win32 API.

## Что внутри
| Модуль | Что делает | Файлы C++ | Где используется на C# |
|---|---|---|---|
| Хеши блоков файла | читает файл и считает SHA-256 каждого блока (4 МиБ) для синхронизации игр между ПК | `block_hasher`, `sha256` | `Service/Sync/SyncManifest.cs` (`ManifestBuilder`) |
| Перехват клавиш киоска | низкоуровневый хук клавиатуры: закрывает Win, Alt+Tab, Alt+Esc, Alt+F4, Ctrl+Esc, Ctrl+Shift+Esc; аварийный выход Ctrl+Shift+F12 трижды | `kiosk_rules`, `kiosk_guard` | `Overlay/KioskGuard.cs` |
| Окна и процессы | какие окна открыты, какое в фокусе, вывести вперёд, закрыть, имя процесса окна, полноэкранное ли чужое приложение | `windows_info` | `Overlay/NativeWindows.cs` (оболочка гостя, `ShellWatcher`) |
| Характеристики ПК | процессор (CPUID), установленная память, видеокарта (драйверы), фиксированные диски, рабочий сетевой адаптер | `hardware` | `Service/HardwareCollector.cs` |

## Как это устроено
- **Интерфейс на чистом C** (`include/clubos_native.h`), версия интерфейса сверяется при загрузке. Исключения через границу DLL не выходят: каждая функция возвращает код результата или безопасное значение.
- **Современный C++20:** RAII для дескрипторов файла, процесса, ключа реестра и объектов криптографии, `std::span`, `std::optional`, никаких сырых `new`/`delete` и ручных буферов. Правила («какие клавиши глотать», «какую видеокарту выбрать») вынесены в чистые функции без обращений к системе и проверяются перебором всех сочетаний.
- **Только системные библиотеки** (`bcrypt`, `user32`, `advapi32`, `dwmapi`, `shell32`, `iphlpapi`, `ws2_32`, `kernel32`). SHA-256 берётся из системной криптографии, своей реализации нет. Среда выполнения Visual C++ вшита (`/MT`): на клубных ПК ничего доустанавливать не нужно. Включены защита потока управления (`/guard:cf`) и предупреждения как ошибки (`/W4 /WX`).
- **Запасной путь.** Обёртки на C# лежат в `ClubOS.Shared/Native/`. Нет DLL рядом с программой (например, на ПК разработчика нет компилятора C++): работает прежний код на C#, результат тот же. `CLUBOS_NATIVE=0` отключает нативный путь. Сверка «нативное = на C#» есть в тестах (`NativeHasherTests`, `NativeSystemTests`).
- **Хеши:** чтение без блокировки файла (Steam может держать его открытым), куски по 1 МиБ, длинные пути больше 260 знаков, отмена флагом, смена размера файла во время подсчёта распознаётся.
- **Перехват клавиш:** вызывать из потока с циклом сообщений (у WPF это главный поток). Нажатия в тестах не имитируются (SendInput ушёл бы в окна живого пользователя): проверяются правило и включение/выключение хука.
- **Характеристики:** каждая часть независима, что не определилось, остаётся пустым и добирается на C#. Видеокарта берётся из драйверов в реестре, а не из DXGI: служба работает в сеансе 0, где DXGI может видеть только программный адаптер.

## Сборка и тесты
Нужны Visual Studio 2022 или Build Tools с компонентом «Разработка классических приложений на C++» (CMake входит).
```
client\ClubOS.Native\build.ps1            # собрать DLL в out\ и запустить тесты (47 штук, GoogleTest)
client\ClubOS.Native\build.ps1 -SkipTests
```
`client\deploy\publish.ps1` вызывает этот скрипт сам; `dotnet build` кладёт готовую `out\clubos_native.dll` рядом со службой и оверлеем (через `ClubOS.Shared`).

## Честно о скорости
Выигрыша в скорости почти нет. Замер подсчёта хешей на файле 1 ГиБ (4 МиБ блоки, файл в кэше): C++ 0,75 с, C# 0,80 с, то есть 5–10%: узкое место и там и там сам SHA-256 (аппаратный, через системную криптографию) и диск. Остальные модули (клавиши, окна, характеристики) вызываются редко и по скорости не ограничены.
Нативная часть сделана потому, что эти задачи по природе относятся к Win32 (хуки, окна, процессы, адаптеры), а не ради ускорения.

## Что на C++ не переносилось и почему
- **Окна и меню (WPF).** WPF на C++ не пишут.
- **Значки программ** (`ProgramIcons.cs`: извлечение значка из exe в PNG): нужны GDI+ или WIC и кодирование PNG, это много кода ради малой пользы.
- **Очистка ПК, связь с сервером, обновления, шифрование ключа** (`ProtectedData`): на C# безопаснее и короче, скорость не важна.
